# kindle2ai

自分が持っている本を、**AI に読み込ませられるファイル**（Markdown / JSONL / プレーンテキスト）に変換する macOS 用ツール。

> [!IMPORTANT]
> **自分が購入した本を、自分で読む・調べるための個人利用ツールです。**
> 抽出したテキストや画像を公開・共有・再配布しないでください。著作権法上の私的複製の範囲を超えます。
> また、Kindle の利用規約は自動化された利用を制限している場合があります。利用は自己責任でお願いします。

Kindle の本の暗号化（DRM）は解除しません。ローカルの本体ファイル（`.kfx` / `.azw`）には一切触れず、
**Kindle アプリの画面を自動でめくりながらキャプチャし、OCR でテキスト化する**方式です。
人が画面を見て書き写すのと同じ経路なので、本の形式（縦書き・固定レイアウト・画像主体）に関係なく動作します。

DRM-free の EPUB / PDF / TXT は、OCR を経由せず直接変換します。

### 精度

青空文庫版の本を Kindle でキャプチャし、青空文庫の原文を正解として**文字誤り率を実測**しています（[詳細](#ocr-精度の評価)）。

| 縦書きの本 | 走れメロス | 人間失格 |
|---|---|---|
| NDLOCR-Lite（任意インストール） | **0.14%** | **0.12%** |
| macOS Live Text（追加インストール不要） | 0.96% | 0.42% |
| 参考: Tesseract `jpn_vert`（初期実装） | 2.78% | 2.53% |

## 必要なもの

| | |
|---|---|
| OS | macOS 13 以上（開発・検証は macOS 15.5） |
| Python | 3.9 以上（macOS 同梱の `python3` で可） |
| ビルド | Xcode Command Line Tools（`xcode-select --install`） |
| Python パッケージ | **なし**。pip install は不要です |
| 縦書きの本 | 追加インストール不要。より高精度にするなら `./setup-ndlocr.sh`（任意、約700MB） |

### OCR エンジンの使い分け

| | エンジン | 備考 |
|---|---|---|
| **横書き** | macOS Vision | 標準搭載、高速、追加インストール不要 |
| **縦書き（推奨）** | NDLOCR-Lite（国立国会図書館） | 任意インストール。誤り率は Live Text の約1/4 |
| 縦書き（既定） | macOS Live Text（VisionKit） | 標準搭載。従来の Vision API は縦書きを一切読めません（検出0行） |
| 縦書き（macOS 13 未満） | Tesseract `jpn_vert` | 誤り率は Live Text の約3倍。`--engine tesseract` で強制も可 |

どちらを使うかは**自動判定**します。数ページを Vision で認識させ、ほとんど読めなければ
（Tesseract があれば両者の文字数を比べて）縦書きと判断し、NDLOCR-Lite（インストール済みなら）か Live Text に切り替えます。

## セットアップ

```bash
git clone https://github.com/washi-9/kindle2ai.git
cd kindle2ai

# macOS 13 未満で縦書きの本を読む場合のみ
# brew install tesseract

# ネイティブヘルパーのビルドと日本語 OCR モデルの取得
./setup.sh

# 任意: 縦書きの精度を上げる NDLOCR-Lite（Python 3.10〜3.13 が必要、約700MB）
# kindle2ai 本体とは別の venv（build/ndlocr-venv）に入るので本体は pip 不要のまま
./setup-ndlocr.sh

# 権限の確認とリクエスト
./bin/kindle2ai doctor --request
```

`doctor --request` は macOS の権限ダイアログを開きます。次の2つを **ターミナルアプリに対して** 許可してください。

1. **システム設定 > プライバシーとセキュリティ > 画面とシステム音声の収録**
   → 許可しないとキャプチャが真っ白になります
2. **システム設定 > プライバシーとセキュリティ > アクセシビリティ**
   → 許可しないとページ送りのキーが効きません

> **許可後はターミナルを必ず再起動してください。** 再起動するまで反映されません。

再度 `./bin/kindle2ai doctor` を実行し、全項目が `[ok]` になれば準備完了です。

## 使い方（アプリ）

`./setup.sh` を実行すると `build/Kindle2AI.app` ができます。Finder でダブルクリックするか `open build/Kindle2AI.app` で起動します。

1. 画面上部で環境を確認します。権限が足りなければ「権限をリクエスト」→ システム設定で **Kindle2AI** を許可 → アプリを再起動
2. 左の一覧から本を選び（最後に開いた順）、ページ数・OCR エンジン・出力形式を設定
3. 「変換を開始」を押し、案内に従って Kindle で本の最初のページを表示してから「開始」
4. 撮影 → 文字認識 → ファイル作成の進捗が表示されます。完了したら「Finder で表示」「Markdown を開く」

撮影中に「ここで撮影を終えて変換」を押すと、そこまでのページで変換します。前回の撮影が残っている本は、続きから再開できます。
「ファイルを変換」タブでは、DRM のない EPUB / PDF / TXT をドロップするだけで変換できます。

アプリは内部で下記のコマンドを実行しているだけなので、コマンドラインと同じ結果になります。
権限はアプリから使う場合は Kindle2AI に、ターミナルから使う場合はターミナルアプリに付与します。
アプリは既定で ad-hoc 署名のため、ビルドし直すたびに macOS が以前の許可を無視します（設定画面ではオンのままに見えます）。
`./tools/make-signing-identity.sh` を一度実行して自分専用の署名用証明書をキーチェーンに作っておくと、
`./setup.sh` がそれで署名し、ビルドし直しても許可が保たれます。

## 使い方（コマンドライン）

### 1. 蔵書を確認する

```bash
./bin/kindle2ai books                  # 全件
./bin/kindle2ai books メロス           # タイトル / ASIN で検索
```

```
ASIN         DL      LOC  TITLE
B009IY56Q2   yes     244  走れメロス
B009IXASIE   yes    1726  人間失格
```

`DL` はローカルにダウンロード済みか、`LOC` は本の総位置数（ページ数の目安）です。
一覧は**最後に開いた順**に並ぶため、先頭が今 Kindle で開いている本です。

### 2. 本を変換する

**Kindle アプリで対象の本を開き、読み始めたいページを表示してから**実行します。

```bash
./bin/kindle2ai run --out out/book --pages 400 --crop-bottom 0.06
```

`run` は以下を一気に行います。

1. `capture` — ページを送りながら1ページずつ画面をキャプチャ
2. `ocr` — Vision でテキスト認識（並列実行）
3. `build` — 整形して Markdown / JSONL / TXT を出力

書名は蔵書DBの**最後に開いた本**から自動で判定します（Kindle のウィンドウタイトルは常に "Kindle" で
書名が入らないため）。違う本が選ばれた場合は `--book '書名'` で指定してください。

実行中は**キーボードに触れず、ウィンドウも動かさないでください**。送ったキーが別のアプリに入ってしまいます。
`Ctrl-C` で中断でき、`--resume` で続きから再開できます。

### 3. 出力

```
out/book/
├── pages/              キャプチャした PNG（確認・再 OCR 用。不要なら削除可）
├── state.json          再開用の状態
├── ocr.jsonl           ページごとの OCR 生データ（行・信頼度・レイアウト）
├── <書名>.md           ← 人が読む / そのまま AI に渡す
├── <書名>.txt          ← プレーンテキスト
└── <書名>.jsonl        ← RAG 用チャンク（ページ番号付き）
```

Markdown にはメタデータ（YAML front matter）、章見出し、`<!-- page N -->` の出典コメントが入ります。
JSONL は 1 行 1 チャンクで、`chunk_id` / `page_start` / `page_end` / `text` を持つため、
そのままベクトル DB や RAG パイプラインに流せます。

## 本の種類ごとの推奨オプション

### 横書きの技術書・ビジネス書（既定）

```bash
./bin/kindle2ai run --out out/book --pages 600 --crop-bottom 0.06
```

### 縦書き（縦書き）の本

既定のまま実行すれば、ページ送りキーも OCR エンジンも自動で判定されます。

```bash
./bin/kindle2ai run --out out/novel --pages 400
```

確実に指定したい場合のみ `--orientation vertical`（Live Text を直接使い、判定を省略）。

### 見開き2ページ表示

```bash
./bin/kindle2ai run --out out/book --columns 2
```

空白の綴じ目（ノド）を検出して自動分割しますが、`--columns 2` で強制できます。
縦書きの見開きは右ページから読む順に並べ替えます。

### 多言語が混じる本

```bash
./bin/kindle2ai run --out out/book --langs ja-JP,en-US,ko-KR
```

`--langs` に無い言語は別の文字に誤認識されます。必要な言語をすべて並べてください。

## 段階的に実行する

`run` は3つのサブコマンドをまとめたものです。設定を変えて OCR や整形だけやり直せます。

```bash
./bin/kindle2ai capture --out out/book --pages 300     # キャプチャのみ
./bin/kindle2ai ocr     --out out/book --langs ja-JP   # 画像は再利用して OCR だけ
./bin/kindle2ai build   --out out/book --formats md    # OCR 結果から整形し直す
```

整形結果が気に入らないときは `build` だけを何度でも試せます（キャプチャし直し不要）。

| オプション | 効果 |
|---|---|
| `--fill-threshold 0.95` | 段落の切れ目を増やす（既定 0.90。改行が多すぎる場合は下げる） |
| `--keep-headers` | ヘッダー・フッターを除去しない |
| `--crop-top 0.08` | 上部のツールバーを無視する割合 |
| `--chunk-chars 1200` | JSONL の 1 チャンクあたりの文字数 |
| `--engine tesseract` | エンジンを固定する（`auto` / `vision` / `livetext` / `ndlocr` / `tesseract`） |
| `--scale 2` | OCR 前に拡大する（**既定1.0。実測では拡大は精度を下げます**） |
| `--no-contrast` | コントラスト補正を無効化する |
| `--keep-ruby` | 縦書きでルビを消さずに OCR する（既定では消す） |
| `--crop-top 0` | ツールバーのクロップを無効化する |

## DRM-free ファイルの変換

```bash
./bin/kindle2ai local ~/Downloads/book.epub --out out/book
./bin/kindle2ai local ~/Downloads/paper.pdf --out out/paper
```

- **EPUB** — spine の順に本文を抽出。ルビ（`<rt>`）は除去し、見出し階層は Markdown に変換します
- **PDF** — 埋め込みテキスト層をそのまま使用。テキスト層が無いスキャン PDF は自動で画像化して OCR します（`--dpi 300` で精度向上）
- **TXT / HTML** — 正規化して段落化

## 仕組み

```
Kindle.app ──[本文エリアをクリックしてフォーカス]
            ──[ページ送りキーを自動判定]
            ──[screencapture -l<window>]──> PNG
                                            │
                      [横書き: Vision / 縦書き: NDLOCR-Lite or Live Text]
                                            │
                              行テキスト + 座標 + 信頼度
                                            │
                    [レイアウト解析] 縦書き判定 / 見開き分割 / 読み順整列
                                            │
                      [前処理] ツールバー除去 + コントラスト補正
                                            │
                    [整形] 全半角正規化・UI 除去・ヘッダー除去
                           行→段落の再構成・ページ跨ぎの結合
                                            │
                          Markdown / JSONL / TXT
```

テキスト整形で特に効いている処理：

- **日本語は空白なしで結合**、英語は空白ありで結合、行末ハイフンは除去して単語を復元
- **段落の判定**は行頭の全角スペースと、行がどこまで伸びているか（`fill`）で行う
- **ページ跨ぎの文**は、前ページが句点で終わっていなければ結合する
- **Kindle の UI**（`位置No. 1234 of 6420`、`45%`、`残り3時間`、ページ番号）を除去
- **柱（ヘッダー）**は複数ページに繰り返し現れる行として検出。ただし句点で終わる行は本文とみなして残す

**ページ送りキーは自動判定**します。right / left / space / pagedown を順に試し、
実際に画面が動いたものを採用します（縦書き・右綴じの本は right が無反応で left が正解）。
その前に**本文エリアを1回クリック**します。アプリを最前面にするだけでは、
キーボードフォーカスがツールバーに残っていて矢印キーが一切届かないことがあるためです。

ページ送りの終端は、**画面が変化しなくなったこと**（3回連続）で判定します。
判定は 256×256 のグレースケールに縮小した画素比較で行います。64ビットの知覚ハッシュでは
どのページも「白地に文字ブロック」に潰れて区別できず、2ページ目を本の終わりと誤判定します。
実測で、異なるページは画素の約6〜7%が変化し、同一ページは0%です（閾値は1%）。

ページ送りアニメーション中の撮影を避けるため、連続2フレームが一致するまで待ってから採用します。
また**最初のページ送りで画面が変化しなかった場合**は「本の終わり」とは扱わず、
キーが効いていない可能性を具体的に指摘して停止します。

## OCR 精度の評価

精度は推測せず測定しています。`eval/` に、**Kindle と同じ描画条件
（セピア背景 RGB(251,241,218)・明朝体・実測した文字サイズとコントラスト）で
正解が既知の縦書きページを合成**し、文字誤り率(CER)を計算する仕組みがあります。
著作物を書き写すことなく、絶対精度を数値で比較できます。

```bash
swiftc -O tools/RenderSample.swift -o build/render-sample
python3 eval/evaluate.py --sizes 20,24,30,38
```

### 測定結果

合成ページ（正解既知、文字サイズ24px）での文字誤り率:

| 前処理 | CER | 精度 |
|---|---|---|
| なし | 1.5% | 98.5% |
| クロップのみ | 1.5% | 98.5% |
| **クロップ + コントラスト補正** | **1.4%** | **98.6%** |
| クロップ + 2倍拡大 | 2.3% | 97.7% |
| クロップ + 2倍拡大 + コントラスト | 2.1% | 97.9% |

実ページ（『論点思考』6ページ）での Tesseract 信頼度とノイズ文字率:

| 前処理 | 信頼度 | 低信頼行 | ノイズ |
|---|---|---|---|
| なし | 0.765 | 22.1% | 0.30% |
| **クロップ + コントラスト補正** | **0.851** | **14.7%** | **0.24%** |

**拡大は信頼度を上げるのに精度を下げます。** 信頼度は「自信を持って間違える」ケースを
検出できないため、既定では拡大しません。`--scale 2` で試すことはできます。

PSM（レイアウト解析モード）も 1/3/4/5/6/11/12 を比較し、縦書きでは **psm 5 が最良**
（CER 1.4%、psm 4・6・11 は CER 95%超で破綻）であることを確認して採用しています。

### 青空文庫との突き合わせ（真の精度測定）

著作権切れの作品なら、**青空文庫の原文を正解データとして実際の Kindle 描画を採点**できます。
合成ページと違い、本物の出版物・本物のレンダリング・本物のパイプラインでの実測値です。

```bash
# 青空文庫版（無料）を Kindle で開いてキャプチャしたあと
./bin/kindle2ai run --out out/走れメロス --pages 40
python3 eval/compare_aozora.py --aozora eval/texts/hashire_merosu.txt \
                               --ocr out/走れメロス
```

レポートの内容:

- **ルビの扱い** — ルビ有り／無しの両方の正解と照合し、どちらに近いかでルビの混入を判定
- **文字誤り率** — 置換・脱落・余分の内訳つき
- **文字種別の誤り率** — 漢字／ひらがな／カタカナ／約物／英数
- **誤変換の内訳** — どの文字がどの文字に化けたかの一覧

照合はアンカー方式（両テキストに一度だけ現れる n-gram を固定点にする）なので、
作品の一部だけをキャプチャしていても正しく位置合わせされ、未照合部分は
誤りではなく「キャプチャ欠落」として除外されます。底本が違う版を渡した場合は
採点せずに拒否します。

> 比較には**青空文庫版の Kindle 本**（¥0）を使ってください。商業出版の文庫版は
> 底本が異なり、OCR の誤りではない差分が大量に出ます。

### 実測結果（青空文庫版）

`<書名>.txt`（パイプライン全体を通した最終出力）を採点した値です。
改善策は『走れメロス』で調整し、調整に使っていない『人間失格』で効果を確かめています。

| | 走れメロス（約1万字） | 人間失格（約7万字） |
|---|---|---|
| Tesseract（初期状態） | 2.78% | 2.53% |
| Tesseract + 補正 + ルビ除去 | 2.67% | 1.96% |
| Live Text + 補正 + ルビ除去（既定） | 0.96% | 0.42% |
| NDLOCR-Lite + ルビ除去 | 0.45% | 0.25% |
| **NDLOCR-Lite + ルビ除去 + 分割再認識（`setup-ndlocr.sh` 後）** | **0.14%** | **0.12%** |

- **NDLOCR-Lite** — 文字の置換誤りが非常に少ない一方、行の一部（5〜17文字）を丸ごと読み飛ばしたり、
  同じ句を繰り返して出力したりする失敗がありました。前者は「行枠の縦横比から期待される文字数に対して
  認識結果が 85% 未満」、後者は「5文字以上の句が1行に2回現れる」で検出し、その行だけを
  **重なりを持たせた上下2分割で読み直して**、重なり部分で結合します（`src/kindle2ai/ndlocr_runner.py`）。
  切れ目は文字の間（インクの最も少ない行）に置き、継ぎ目にゴミ文字が出ても許容します。
  なお、行全体を大きいモデルで読み直しても同じ箇所を飛ばすため効果はありませんでした
  （このあたりの調整には両方の本を使ったため、人間失格も完全な未知データではありません）

- **Live Text** — macOS の「テキスト認識表示」と同じ VisionKit の `ImageAnalyzer`。従来の Vision API
  (`VNRecognizeTextRequest`) と違い縦書きを読めます。特に漢字に強く、漢字の誤り率は Tesseract の約4%に対して約2%でした。
  公開 API は行の座標を返さないため、段落は「行末が句点・閉じ括弧で終わるか」で判定します
- **ルビ除去** — 縦書きでは、本文の列の右に細い帯として並ぶルビを画像から検出して白く塗りつぶします。
  本文の列はおよそ30px、ルビは9〜14pxで、本文の列から1〜4px右に接しています。この条件に合う帯だけを消すので、
  短い本文の行を消してしまうことはありません。Live Text でも誤り率が下がりました（1.64% → 1.11%、人間失格 0.99% → 0.67%、いずれも整形前）
- **三点リーダ** — Live Text は「……」を `・・・・・・` と、Tesseract は `:::` や `:……` と読むため、連続を「……」に戻します
- **小書き仮名の重複**（Tesseract のみ） — 「いぃい」「ぃい」「いぃ」を1文字に戻します
  （正解テキストに大小の同じ仮名が隣接する例は無く、3連の場合も 33/35 件が1文字でした）。っ/ッ は対象外です

Live Text では拡大（1.5倍・2倍）もコントラスト補正も結果がほぼ変わらず、2値化は悪化しました（0.67% → 1.08%）。
残る誤りは「信→倍/借/言」「っ→つ」や、婿・磔などの難しい漢字が中心です。

<details><summary>Tesseract で分かったこと</summary>

ルビ付き漢字の誤り率が高い（26.7%）のは、ルビそのものの影響よりも、元々難しい漢字にルビが付いているためでした。
1つの漢字を上下に割って余分な文字（和・人・上・有）を出す分割誤りも Tesseract 固有です。
OCR の信頼度は誤りとほとんど相関しないため（0.9以上の行でも 2.5%）、怪しい行の検出には使えません。
</details>

### 文字サイズの影響

文字サイズ 20〜38px の範囲では CER は 1.4〜2.3% でほぼ横ばいでした。
Kindle のフォントサイズを上げても劇的な改善は見込めません。
効くのは**ツールバーのクロップとコントラスト補正**です。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| キャプチャが真っ白／デスクトップだけ | 画面収録を許可し、**ターミナルを再起動** |
| 「No key turned the page」で停止する | 本の最終ページにいないか確認。Kindle の本文エリアを手動で一度クリックしてから再実行 |
| 縦書きなのに文字がほとんど取れない | `doctor` で「vertical JP」が `[ok]` か確認（macOS 13 未満は `brew install tesseract` と `./setup.sh`） |
| 誤字が多い | `build` が表示する信頼度を確認。低信頼行が多いならウィンドウを大きくして再キャプチャ |
| 本文の端が切れる | `--crop-top 0 --crop-bottom 0` でクロップを無効化 |
| 1〜数ページで終わってしまう | `--delay 2.0` に増やす（描画が間に合っていない） |
| 文字化け・別言語に誤認識 | `--langs` にその言語を追加する |
| 文章がぶつ切りになる | `--fill-threshold 0.95` |
| 段落が全部くっつく | `--fill-threshold 0.80` |
| ページ番号や柱が本文に混ざる | `--crop-top 0.08 --crop-bottom 0.08` |
| 途中で止まった | `--resume` を付けて再実行 |

OCR の精度は元の表示サイズに比例します。**Kindle アプリを大きく表示し、文字サイズを上げる**と
認識率がはっきり改善します。
